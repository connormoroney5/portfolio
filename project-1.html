CyBot navigation

A Roomba-based robot that finds its way through an obstacle field, guided by a Python GUI I built.

Add the GUI screenshot (object map and path) or the interface sketch here

Description

In CPRE 2880: Embedded Systems, each team received a “CyBot”: a Roomba robot carrying a Tiva TM4C123GH6PM microcontroller, plus a servo-mounted IR sensor and PING (ultrasonic) sensor. We wrote C code to drive the robot and track where it was using those sensors. The final challenge was to steer the CyBot through a field of obstacles and reach a target end zone.

Our team decided navigation would be much easier if we could see the field, so we built a GUI that plots detected objects and the path the CyBot has traveled. The GUI talks to the robot over UART, sends commands, and uses encoder counts and sensor scans to place the robot and each object on a map. It also shows a polar plot of the latest scan.

To test without a physical robot, I wrote a “Mock CyBot”: a program that accepts the same navigation commands as the real one but returns simulated movements. That let me fix GUI problems before we ever touched the hardware. In our demo, the TA called our navigation “really impressive.”

My role

I wrote a large share of the C code for the CyBot and was the main developer of the GUI. I designed and programmed it in Python and built the Mock CyBot used to test it. The team worked together on the overall interface design (sketched above) and on testing the robot in the field.

Skills and knowledge gained

  • Embedded C: sensors, servo (PWM), UART communication, and encoder-based position tracking
  • Python: building a live GUI that plots robot position and detected objects
  • Testing with simulation: building a mock device so software can be debugged without hardware
  • Teamwork: agreeing on an interface early so firmware and GUI could be built in parallel
